Alfred Smart Systems. Tecnología inteligente para la gestión digital de edificios y oficinas.

Contexto

Alfred Smart es una plataforma de gestión de inmuebles inteligentes que opera en múltiples verticales: Home, Offices, Built-to-Rent, Hotels y Parkings. El producto se compone de: - App para tenants (control de accesos, climatización, reservas, etc.) - Assets Manager (web) para property managers - Infraestructura IoT integrada (cerraduras, sensores de clima, sensores de consumos, etc.) Cada vertical tiene: - Stakeholders distintos - Casos de uso diferentes - Ciclos de estancia variables - Diferentes niveles de complejidad operativa. El desafío no consistía en diseñar una nueva funcionalidad por vertical, sino en transformar una base tecnológica en un sistema de producto coherente, capaz de escalar entre distintos modelos de negocio. Problemas estructurales: - La experiencia variaba según vertical. - Las decisiones de diseño eran reactivas a necesidades comerciales. - No existía una lógica clara de qué era core y qué era específico. - El desarrollo comenzaba a desacelerarse por complejidad acumulada.

Probar demo

La metodología consistió en un análisis heurístico de la plataforma, creación de un Design System siguiendo el diseño centrado en el usuario, ideación y validación.

El objetivo era: - Reutilizar componentes entre verticales. - Adaptar arquitectura sin duplicar producto. - Alinear app móvil y web bajo una misma lógica. - Preparar el producto para un modelo SaaS escalable. El impacto fue claro en: 1) Producto - Base coherente multi-vertical. - Reducción de inconsistencias. - Arquitectura modular sostenible. 2) Negocio - Mayor capacidad de adaptación a nuevas oportunidades. - Herramienta comercial funcional. - Preparación para modelo SaaS. 3) Diseño - Sistema vivo transversal. - Cultura de validación operativa. - Reducción de decisiones ad-hoc.

Aprendizajes

- Escalar verticales sin sistema genera deuda estructural. - Un design system es infraestructura estratégica, no solo UI. - Las soluciones ad-hoc suelen ocultar necesidades sistémicas. - Validar en contexto operativo cambia decisiones clave. - En productos B2B2C, la operación define la experiencia.
